About SafePath & Optimization Methodology

Academic background, transparent mathematical formulations, and Python concept mapping.

Research Question

“How can personal safety and travel time be jointly optimized in urban pedestrian navigation, and how sensitive is the route recommendation to changing safety factor weights?”

Python Concepts Demonstrated

  • Dictionaries & Lists: Adjacency graph & segment attributes
  • Functions: Modular scoring, pathfinding & Pareto filter
  • Conditionals: Soft high-risk thresholds & time-of-day adaptation
  • File Handling: JSON serialization & safety report export

Extensibility Roadmap

Designed with decoupled scoring and routing functions so simulated 0–10 segment arrays can be swapped with live OpenStreetMap Overpass lighting tags, GPS telemetry, and municipal crime APIs.

Methodology & Transparent Mathematical Formulas (Click to Collapse / Expand) ▼

1. Segment Safety Score S(e) ∈ [0, 100]

Each factor is scored 0–10 (higher = safer, with isolation and historical incident risk inverted as 10 - value). Weights are normalized so Σwᵢ = 1:

S(e) = 10 × (w_light·F_light + w_crowd·F_crowd + w_cctv·F_cctv
            + w_emerg·F_emerg + w_isol·(10 - isol) + w_risk·(10 - risk))

Time-of-day modifies effective lighting and crowd density on poorly lit or park-adjacent corridors. Any segment with S(e) < 40 is classified as High-Risk.

2. Route-Level Aggregation

For a candidate route P = (e₁, …, eₖ):

Length(P) = Σ d(e)    Time(P) = Σ t(e)
Safety(P) = [Σ S(e) · d(e)] / Length(P)

Candidate simple paths are discovered via bounded graph search + weighted Dijkstra passes, then evaluated for Pareto dominance in (Safety(P), -Time(P)).

3. Comparison of Strategies 1–3

  • Shortest/Fastest: Minimizes Time(P) purely.
  • Safety-Only: Maximizes Safety(P) purely, ignoring travel time penalties.
  • Fixed Weighted: Minimizes w_s·(1 - Safety(P)/100) + w_t·(Time(P)/Time_max) using static slider weights (default 0.70 / 0.30) with no segment-level risk threshold.

4. Proposed Adaptive Multi-Objective Utility

U_safe(P) = (S(P) - S_min) / (S_max - S_min)
U_time(P) = (T_max - T(P)) / (T_max - T_min)
Utility(P) = w_s_adapt · U_safe(P) + w_t_adapt · U_time(P) + 0.12 · (min_e S(e)/100)

Adaptation & Soft Constraint: Night adds +0.22 to safety weight, Evening adds +0.10, active disruptions add +0.12, and user Risk Preference sets the baseline. Candidate paths with HighRiskSegments > 0 are excluded unless no zero-risk path exists.
